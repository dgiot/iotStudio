# IO 服务器全面体检与 Modbus 动态感知方案

> 定位: 大庆油田时序数据采集项目 — 老系统"搭桥手术"专项
> 原则: ① 不修改 DTU ② 不影响 A11 正常使用 ③ 全部被动/只读
> 关联: 技术方案应答书 模块2/模块3 落地实现

---

## 一、背景与约束

### 1.1 为什么要"搭桥"

```
现状 (生产链路, 不能动):
RTU ──TCP:53001──→ CommBridge ──WM_COPYDATA──→ IoMonitor ──OLEDB──→ Oracle
DCS ──DCOM:135───→ IOMan ────psAPI──→ pSpace ────IoCommit──→ Oracle
A11 ──TCP:8889───→ IOMan ────psAPI──→ pSpace ────────────────→ Oracle
```

- 191 台 RTU 采集节奏 1s、OPC DA 5 个 DCS 订阅、A11 7 通道 1-5s
- **不能碰**: CommBridge :53001 查询节奏 / DCOM 重连 / OLEDB 写竞争
- 类比: 给活人移植心脏 — 移植前必须全面体检, 移植方式是"搭桥"而非"换心"

### 1.2 硬约束

| # | 约束 | 实现方式 |
|---|------|----------|
| 1 | 不修改 DTU | 被动监听, 零发包, 不建立任何 TCP 连接 |
| 2 | 不影响 A11 正常使用 | 原链路原样保留, 只镜像流量 (Npcap 旁路) |
| 3 | 术前全面体检 | 8 维度体检 + 多作业区台账, READY 才允许搭桥 |

## 二、模块一: IO 服务器术前全面体检

### 2.1 架构

```
┌──────────────────────────────────────────────────────┐
│  IO 服务器 (11.66.12.x)                              │
│  WinRM 只读采集 (进程/端口/资源)                      │
│  Npcap 旁路镜像 (协议帧/链路统计)                     │
└──────────────┬───────────────────────────────────────┘
               │ 只读
      ┌────────▼────────┐
      │ IOHostHealthChecker │  8 维度体检
      └────────┬────────┘
      ┌────────▼────────┐
      │  HealthLedger   │  多作业区台账 (READY/CAUTION/BLOCKED)
      └─────────────────┘
```

### 2.2 体检维度 (8 项)

| # | 维度 | 检查内容 | 131 实测基准 |
|---|------|----------|-------------|
| 1 | 采集节拍 | CommitRealSpan/HisSpan/TagOnce 合规 | 300ms/500ms/15000点 |
| 2 | 资源余量 | CPU/内存/磁盘/TCP 连接 | 5%/30%/203 |
| 3 | 进程健康 | CommBridge/IOMan/IoMonitor/IoCommit | 全部在 |
| 4 | 端口监听 | 53001/8889/135/7001 | 全部监听 |
| 5 | 链路状态 | RTU 连接/OPC DCOM/A11 通道 | 191/5/7 |
| 6 | 协议合规 | 帧异常率 (被动监听统计) | 0.017% |
| 7 | 冲突边界 | OLEDB 空闲/提交窗口 | 3/240ms |
| 8 | 数据健康 | 点表规模/写库延迟 | 46709点/700ms |

### 2.3 判定标准

```
READY   (全绿, ≥90分)  → 允许搭桥
CAUTION (有黄项)       → 处理后搭桥 (限流/错峰)
BLOCKED (有红项)       → 禁止搭桥 (先修复)
```

### 2.4 API

```
POST /api/passive/health/io/{ip}      单机体检 (可注入 scan_data 或 WinRM 实时)
POST /api/passive/health/ledger       多作业区批量体检台账
```

## 三、模块二: Modbus 动态感知与物模型自动匹配

### 3.1 架构

```
┌──────────────────────────────────────────────────────────┐
│  新 RTU 上线 (动态 IP, 11.248.x)                         │
│  └── TCP 连接建立 ──→ Npcap 旁路感知 (零发包)            │
└──────────────────────┬───────────────────────────────────┘
                       │
      ┌────────────────▼────────────────┐
      │  DynamicModbusScanner           │  只读 FC03 扫描
      │  · 从站发现 (1-247)             │  + 采样识别
      │  · 点位识别 (类型/字节序/缩放)   │
      └────────────────┬────────────────┘
                       │ 识别点位列表
      ┌────────────────▼────────────────┐
      │  OilfieldModelMatcher           │  G1-G8 物模型
      │  · 地址对齐 + 量程校验 + 类型校验 │  64 点油水井表
      └────────────────┬────────────────┘
                       │ 匹配报告
      ┌────────────────▼────────────────┐
      │  自动配点表 (auto_point_table)   │  → 采集配置导入
      │  · 零修改: 不碰 CommBridge :53001│
      └─────────────────────────────────┘
```

### 3.2 G1-G8 油水井标准物模型 (64 点)

| 组 | 名称 | 寄存器基址 | 典型点位 |
|----|------|-----------|----------|
| G1 | 基础工况 | 40300 | 油压/套压/回压/载荷/动液面/含水率 |
| G2 | 电参 | 40351 | 三相电流/电压/功率/功率因数 |
| G3 | 变频参数 | 40400 | 频率/变频器温度/状态/故障码 |
| G4 | 抽油机 | 40420 | 冲次/冲程/泵径/沉没度 |
| G5 | 螺杆泵 | 40430 | 转速/扭矩/扬程/容积效率 |
| G6 | 报警诊断 | 40440 | 终端状态/仪表故障码/AI报警 |
| G7 | 仪表扩展 | 40450 | 无线压力/温度/示功仪/电池 |
| G8 | 变频扩展 | 40550 | 功率平衡/间抽控制/PID |

### 3.3 识别算法

```
候选判定: 可读 && 非 0xFFFF && 非全零
类型推断: uint16 / uint32 / float32 (32bit 组合合理性)
字节序:   AB (大端标准) / BA (小端)
动态性:   连续采样变化 → 动态点 (遥测) / 静态点 (状态/配置)
缩放:     依据量程推断 (压力 0.01 / 电流 0.1)
```

### 3.4 闭环验证 (11/11 通过)

```
模拟抽油机 RTU → 扫描识别 7 点 → 物模型匹配率 100%
油压 40300 ✓ / 套压 40301 ✓ / 载荷 40304 ✓
电流 40351 ✓ / 冲次 40420 ✓ / 状态点静态识别 ✓
自动配点表生成 ✓ / 零修改验证 (仅 FC03 只读) ✓
```

### 3.5 API

```
GET  /api/passive/devices      发现的设备 (动态 IP 感知)
GET  /api/passive/points       学习到的点位
GET  /api/passive/events       动态变化事件 (上线/下线/点位)
GET  /api/passive/decoded      解码的数据点
POST /api/passive/start|stop   被动监听启停 (零残留)
```

## 四、验收标准

| # | 验收项 | 标准 | 验证方式 |
|---|--------|------|----------|
| 1 | 零发包 | 监听期间向生产设备发出的包 = 0 | 抓包自证 |
| 2 | 零修改 | RTU/CommBridge 配置 MD5 前后一致 | 配置比对 |
| 3 | 资源增量 | CPU +2~5% / 内存 <100MB | Npcap 实测 |
| 4 | 体检判定 | 8 维度 + 三态结论正确 | 自测 3 场景 |
| 5 | 台账 | 多作业区批量体检 + 最差项 TOP | 自测 4 服务器 |
| 6 | 点位识别 | 类型/字节序/动态性正确率 ≥90% | 闭环测试 |
| 7 | 物模型匹配 | 识别点位 G1-G8 匹配率 ≥80% | 闭环测试 |
| 8 | 自动配点 | 新 RTU 上线自动生成配点表 | 闭环测试 |
| 9 | 无感退出 | 停监听后生产链路零感知 | 无连接残留 |

## 六、与 ThingsBoard 等通用平台的差异

| 维度 | 通用 IoT 平台 (ThingsBoard) | 本项目方案 |
|------|---------------------------|-----------|
| 接入方式 | 设备主动上报 (MQTT/HTTP) | 被动监听老系统流量 (零侵入) |
| 点位管理 | 人工配置设备属性 | 自动识别 + G1-G8 物模型匹配 |
| 老系统兼容 | 不支持 | 搭桥旁路, 原链路零影响 |
| 设备发现 | 设备上线通知 | 被动学习 (新连接/注册帧) |
| 场景绑定 | 通用 | 大庆油田 191 RTU/油水井/A11 专属 |
