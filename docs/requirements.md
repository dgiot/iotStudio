## 1. 项目概述

### 1.1 项目背景

客户需要一个**可源码交付**的轻量级物联网平台，用于光储充微电网场站的数据采集与监控。客户拿到源码后自行掌握二次开发、部署和运维。

**本项目与乙方的自有物联网平台无关**——乙方交付的是一套独立的、基于 Python 全开源技术栈的物联网平台。

### 1.2 项目定位

**学习版 / 轻量版**，核心要求：

- 功能完整：Modbus RTU/TCP、IEC 104、OPC UA 四种协议**实际跑通**
- 源码交付：客户拿到完整源码，可自行编译、部署、二次开发
- 轻量部署：单机即可运行，不依赖企业级中间件
- 预算友好：全开源组件，不产生第三方 License 费用

### 1.3 项目范围

| 范围 | 说明 |
|------|------|
| **包含** | 数据采集引擎、四种协议适配、时序数据存储、关系数据管理、2D 组态、数据推送、管理后台、部署文档 |
| **不包含** | 应用层业务开发（客户负责） |
| **不包含** | 服务器硬件、操作系统、网络环境（客户提供） |

## 2. 功能需求

### 2.1 数据采集

#### 2.1.1 Modbus RTU 采集

| 项目 | 说明 |
|------|------|
| 物理层 | RS-485 串口 |
| 功能码 | 01 线圈、02 离散输入、03 保持寄存器、04 输入寄存器 |
| 数据类型 | int16, uint16, int32, uint32, float32, float64, string |
| 采集模式 | 周期轮询，周期可配置 |
| 多从站 | 同一串口多从站地址轮询 |
| 异常处理 | 超时重试、CRC 校验失败处理、断线重连 |

#### 2.1.2 Modbus TCP 采集

| 项目 | 说明 |
|------|------|
| 物理层 | 以太网，TCP/502 |
| 功能码 | 01、02、03、04、06、16 |
| 采集模式 | 周期轮询 + 变化上报 |
| 多连接 | 支持多设备并发连接 |
| 异常处理 | 连接超时、自动重连 |

#### 2.1.3 IEC 60870-5-104 采集

| 项目 | 说明 |
|------|------|
| 物理层 | 以太网，TCP/2404 |
| 角色 | 主站（控制站），连接从站设备 |
| ASDU 类型 | M_ME_NA_1(9), M_ME_NB_1(11), M_ME_NC_1(13), M_SP_NA_1(1), M_DP_NA_1(3), C_IC_NA_1(100), C_CS_NA_1(103), C_SC_NA_1(45) |
| 传输原因 | 周期(1)、背景(2)、突发(3)、总召(20)、总召响应(21) |
| 功能 | 总召、变化传输、时钟同步 |
| 异常处理 | 连接断开自动重连、序号校验 |

#### 2.1.4 OPC UA 采集

| 项目 | 说明 |
|------|------|
| 角色 | OPC UA Client |
| 安全策略 | None, Basic256Sha256 |
| 认证 | 用户名密码、匿名 |
| 读取模式 | 订阅（Subscription）+ 轮询（Read） |
| 功能 | Browse 地址空间、Read、Write、MonitoredItem |
| 数据类型 | Boolean, SByte, Byte, Int16, UInt16, Int32, UInt32, Int64, UInt64, Float, Double, String |

### 2.2 数据存储

#### 2.2.1 时序数据 — TDengine

| 项目 | 说明 |
|------|------|
| 存储内容 | 设备遥测值（电压、电流、功率、温度、SOC 等） |
| 数据模型 | 超级表 + 子表（每个设备每个点位一个子表） |
| 保留策略 | 1 分钟级数据保留 12 个月，自动降采样 |
| 压缩 | 列式存储，目标压缩比 ≥ 10:1 |
| 查询 API | RESTful 查询接口，支持时间范围、设备、点位等过滤 |

#### 2.2.2 关系数据 — PostgreSQL

| 项目 | 说明 |
|------|------|
| 存储内容 | 设备档案、点位配置、场站信息、告警记录、用户信息、操作日志 |
| ORM | SQLAlchemy + asyncpg |
| 迁移 | Alembic |

#### 2.2.3 轻量模式（可选）

在无 TDengine/PostgreSQL 环境的场景，可降级为 SQLite：
- SQLite 存储设备档案、配置、告警
- JSON 文件存储时序数据（简易模式）
- 适合单机开发测试

### 2.3 2D 组态

| 项目 | 说明 |
|------|------|
| 技术实现 | HTML5 Canvas / SVG，纯前端，无需额外插件 |
| 组件库 | 逆变器、PCS、充电桩、电表、变压器、线缆等电力图元 |
| 数据绑定 | WebSocket 实时数据推送至组态画面 |
| 交互 | 点击设备查看详情、告警变色、数值实时刷新 |
| 画面 | 总览图、光伏画面、储能画面、充电桩画面、碳排仪表盘、告警画面 |
| 编辑 | 拖拽式画面编辑器（可选） |

### 2.4 数据推送

| 项目 | 说明 |
|------|------|
| 推送方式 | MQTT（默认）、HTTP POST |
| 推送模式 | 实时推送（数据变化即推）+ 周期推送 |
| 数据格式 | JSON，结构可配置 |
| 可靠性 | 断网本地缓存（SQLite 暂存），恢复后补推 |
| 目标配置 | 支持配置多个推送目标 |

### 2.5 管理后台

| 功能 | 说明 |
|------|------|
| 设备管理 | 设备增删改查、导入导出 |
| 点位配置 | 点位模板、点位绑定、批量配置 |
| 采集监控 | 采集状态监控、成功率统计、延迟监控 |
| 告警管理 | 规则配置、告警记录、确认/清除 |
| 系统管理 | 用户管理、角色权限、操作日志 |

### 2.6 告警引擎

| 项目 | 说明 |
|------|------|
| 告警类型 | 阈值告警（高/低限）、变化率告警、状态告警（离线/故障） |
| 告警级别 | 紧急(P0)、重要(P1)、一般(P2) |
| 通知方式 | WebSocket 推送至前端 + MQTT 推送至第三方 |
| 处理流程 | 触发 → 通知 → 确认 → 清除 → 归档 |

## 3. 非功能需求

| 需求 | 指标 |
|------|------|
| 设备接入量 | ≤ 500 台（轻量版）|
| 采集周期 | 1~60 秒可配置 |
| 数据完整率 | ≥ 99% |
| 采集延迟 | ≤ 3 秒 |
| 平台可用率 | ≥ 99%（单机） |
| 部署方式 | 单机部署，Docker 可选 |
| 操作系统 | Linux（Ubuntu 20.04+ / CentOS 7.9）|
| Python 版本 | ≥ 3.10 |
| 源码交付 | 完整源码 + Git 仓库 |
