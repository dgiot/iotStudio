# 工业物联网场景下开源时序数据库选型报告
## TDengine vs. TimescaleDB vs. InfluxDB + SQLite 边缘回退方案

> 研究时间: 2026-07-27 | 用途: 时序数据采集与应用管理系统项目技术选型依据

---

## 1. 综合对比表

| 维度 | TDengine 3.x | TimescaleDB 2.x | InfluxDB 3.x | SQLite WAL2 |
|---|---|---|---|---|
| 写入吞吐量 | **220,000 pts/s** | 65,000 | 85,000 | ~1,200 tps |
| 峰值内存 | **0.8 GB** | 3.5 GB | 2.1 GB | <1 MB |
| CPU占用 | **12%** | 68% | 45% | 极低 |
| 压缩比 | **15:1~52:1** | ~1.6:1 | ~3.5:1 | 无列式压缩 |
| 查询延迟(24h聚合) | **12 ms** | 60 ms | 450 ms | 数百ms |
| 边缘部署 | 优秀(0.8GB) | 困难(3.5GB) | 中等(2.1GB) | 极佳 |
| 开源协议 | AGPL v3.0 | Apache 2.0+TSL | MIT | Public Domain |
| MQTT/OPC原生接入 | 内置零代码 | 无 | Telegraf插件 | 无 |

## 2. 性能基准 (TSBS标准套件)

- **写入**: TDengine 是 InfluxDB 的 1.82~16.2x, TimescaleDB 的 1.04~11.6x
- **查询**: TDengine vs InfluxDB 均值 **68.7x**; vs TimescaleDB 均值 **23.3x**
- **存储**: TimescaleDB 磁盘是 TDengine 的 11.6~12.2 倍; InfluxDB 是 2.6~2.8 倍

## 3. 油田案例

- **中石油**: 40+ Oracle → 9套 TDengine, 50,000+口井, 20亿条记录, 压缩率<10%
- **浙江油田**: 52:1压缩比, "一井一表"模型
- **石化炼厂**: ML预测准确率92%, 非计划停机-65%, 年节约4亿+

## 4. 选型建议

- **边缘网关(8-16GB)**: TDengine为主 + SQLite WAL2为缓冲
- **单服务器(32-64GB)**: TDengine首选; 已有PG生态选TimescaleDB
- **集群/多站点**: TDengine SuperNode + taosX边云协同
- **嵌入式(<512MB)**: SQLite WAL2
