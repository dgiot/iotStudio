## 2. 业界界面共识（跨平台一致性最强的 7 条）

1. **导航结构趋同**：总览/驾驶舱 → 设备管理 → 实时数据/采集 → 告警中心 → 数据分析 → 运维诊断 → 系统管理（根云、华为云、ThingsBoard、Azure 高度一致）
2. **首页=KPI 卡片墙**：设备在线率、数据项在线率、模型覆盖率、告警数为必备指标（太钢案例明示），卡片可点击下钻
3. **设备详情页=页签化**：概览/实时数据/历史监控/报警信息/趋势分析/日志（根云、华为云、ThingsBoard 三家同构）
4. **状态机五态+明确判离线规则**：在线/离线/未激活/异常/冻结（华为云，MQTT 断开 1 分钟判离线）
5. **告警=分级+四态生命周期**：五级严重度（ThingsBoard Critical/Major/Minor/Warning/Indeterminate）× 活动/清除 × 确认/未确认；升级链 + 通知中心铃铛 + 多渠道（Web/短信/邮件）
6. **大屏=左中右三区**：顶部通栏（LOGO+时间+状态）、中间 C 位地图/拓扑"一张图"、右侧告警滚动列表；深色底（7×24 点亮）+ 631 配色 + 红仅用于告警 + KPI ≥48px + "3 秒原则"
7. **角色化视图**：厂长/调度/运维千人千面（Azure 四角色、三一决策-生产-维护三层模型）

## 3. 分方向要点

### 3.1 油气行业（对标最直接）

- **梦想云/塔里木**：大屏四界面（生产总况/油气生产管控/钻完井决策/应急指挥）；应急预警弹窗+滚动+语音播报；配产智能工作流（气藏优化 1 个月→20 分钟）；Vue.js 三端同构（与本项目前端技术一致）
- **大庆智慧指挥中心**：一屏统览"探采储运销"全链条，单井在线率 90.6%、数字化覆盖率 97.2%，10 大业务全天候调控
- **长庆**：13 个可视化看板 + 20 余种算法模型，采油时率 98%→98.9%，异常 2 分钟锁定问题井、5 分钟闭环，预警准确率 98.5%；物联网云平台"产量差异分析"十几秒锁定单井减产
- **青海油田**：11 个主题模块导航、"1+4+N"指挥中心、日均同步数据 20 万余条
- **紫金桥采油八厂**（与本系统功能最接近）：数据采集→流程图动态展示→历史趋势→过程报警（按影响安全/生产/普通分类、一/二/三级分级、声光+弹窗）→报表（实时/班/日/月/年）→单井监控（示功图/电参数）
- **ProMACE**：生产运营全景可视化、数字孪生三维建模、连接 75 万+ 设备
- **SLB Avocet ESP Surveillance**：Web 交互式实时监控，聚焦问题井
- **PHD**：无自带大屏界面，前端由第三方承担（说明"实时库厂商界面弱"是行业常态，正是本项目界面价值所在）

### 3.2 工业互联网平台

- **树根根云**：首页统计卡片墙可点击下钻；设备列表地图/卡片双视图；详情页页签=概览/实时数据/监控数据/报警信息（高/低/故障三类）/趋势分析（+导出）/位置/日志
- **华为云 IoTDA**：五态状态机 + 明确判离线规则；详情页含消息跟踪/云端运行日志（故障定位）；设备影子（上报值 vs 期望值）
- **ThingsBoard**：Dashboard 五构件（States 导航/Entity Aliases/网格布局/Actions 联动/Time Window 聚合）；告警五级×四态、沿实体层级传播、升级链；通知中心铃铛；600+ 预置 widget
- **Azure IoT Central**：行业模板起步仪表盘；Jobs 批量操作；角色驱动界面（构建者/操作员/管理员/设备开发者）
- **航天云网生态（瀚云 MES）**：设备状态色块图——运行绿/空闲黄/设定蓝/报警红/离线灰

### 3.3 数据大屏/驾驶舱

- **DataV 官方设计库**：5 套完整可视化套件；"主视觉居中布局"=中央地图 + 四周数据面板（数字翻牌器/饼环/折线柱状/进度条）
- **帆软**：六大区块（顶部总览/主指标 1-3 个大字/分区指标/趋势与异常预警居中/交互操作/辅助信息）；3 秒原则、1 屏原则、每屏 6-8 图、交互 ≤1s
- **配色**：深蓝灰暗色底 + "631"（主 60%/辅 30%/强调 10%）+ 语义色三色（绿正常/琥珀警告/红告警，红仅用于告警）；数字等宽字体+千分位
- **电网"一张图"**：拓扑态势 + 多业务系统数据集中 + 设备状态实时监控 + 故障快速研判
- **三一/树根**：设备实时定位 + 三维动画工作状态 + 大数据分析预测；决策层/生产层/维护层三类角色"看管控"一体化
- **刷新频率（无权威规范，业界惯例）**：KPI/告警秒级（WebSocket 推送或轮询）、趋势图 5-30 秒、交互联动响应 ≤1 秒、动画 ≤1 秒

### 3.4 SCADA/设备管理

- **WinCC 定式**：监控画面三段式=报警条（常驻，危险时闪烁+声音）+ 主显区（趋势/参数/报警/报表）+ 按钮区；画面组织"设备总貌 → 分流程画面"
- **iFIX 链路状态码**：comm=通讯中断 / CFN=设备故障 / OK=运行正常——采集链路健康呈现的经典做法
- **施耐德 Citect**：情境感知布局 + 设备驱动界面；按设备显示最高优先级报警摘要（设备维度聚合，适合场站巡检）
- **组态王/力控**：工程浏览器集中管理；云版一次开发多端运行
- **ThingsBoard 设备详情页**：属性/最新遥测/计算字段/告警规则/告警/事件/关系/审计日志/版本控制——"台账+实时数据+告警"三联 Tab
- **映翰通 Device Manager**：设备信息含配置状态/信号强度/IMSI/IMEI；事件告警（online/offline、流量告警、双 SIM 切换、链路备份、接口 up/down）；GIS 地图实时位置
- **明确缺口**：① 油田场站专用 SCADA 界面公开渠道无一手来源；② **"缓存补传进度"界面任何厂商公开页面均未找到**——断网缓存补传的可视化是本项目可打造的差异化界面

## 4. 八张界面对照（业界做法 vs 我们规划 vs 建议）

| 我们的界面 | 业界对应做法 | 差距与建议 |
|-----------|-------------|-----------|
| **① 数据驾驶舱** | 油田大屏第一 KPI=设备在线率（长庆 98.9%/大庆 90.6%）；左中右三区；C 位地图/拓扑"一张图"；右侧告警滚动列表；KPI ≥48px 数字翻牌；深色底 631 配色 | **吻合度高**。建议：① C 位用"采集链路拓扑图"承担视觉锚点（无地理数据，拓扑等效电网"一张图"）；② 告警热力主形式对齐滚动列表+红色高亮，热力图作增强；③ 顶部 KPI 区包装"结果性指标口径"（见第 5 节） |
| **② 设备与测点管理** | 设备列表（状态筛选+搜索+批量操作+Excel 导出，华为云/根云）；五态状态机+明确判离线规则；详情页页签=概览/实时/历史/报警/趋势/日志 | 建议：① 设备状态五态+判离线规则写入界面说明；② 设备详情页采用六页签（台账/实时/历史/告警/趋势/采集日志）；③ "自动配点"对标"模型覆盖率"指标口径 |
| **③ 采集监控** | iFIX comm/CFN/OK 链路状态码；映翰通链路事件（online/offline、双 SIM 切换、接口 up/down）归入事件告警；WinCC 报警条常驻 | 建议：① 链路状态用状态码+语义色（正常/降频/离线/告警）；② **断网补传进度界面是业界公开缺口——作为本项目差异化亮点**（报价表已有"断网缓存与补传"计价项，界面配套自然） |
| **④ 算法管理** | 长庆 20+ 算法模型看板；镇海炼化八类高级报警（"人找信息→信息找人"）；ThingsBoard 规则链可视化 | 建议：① 加"算法覆盖率/命中率"指标展示（对标长庆预警准确率 98.5% 考核口径）；② 算法版本对比（A/B）+ 回滚已有，可补"生效范围"可视化 |
| **⑤ 告警中心** | 五级严重度×四态生命周期（ThingsBoard）；分类分级（长庆按安全/生产/普通）；声光+弹窗+语音播报（塔里木）；升级链+多渠道（Web/短信/邮件）；通知中心铃铛 | 建议：① 补齐"确认/清除"双运维动作 + 未确认未清除计数（业界硬性惯例）；② 加告警升级链（延迟逐级通知、确认即停）；③ 顶部铃铛未处置数已有，可补"按级别红点" |
| **⑥ 数据分析与报表** | 班/日/月/年报（紫金桥/组态王惯例）；时间轴拖拽回放（故障复盘）；长庆产量差异分析 2 分钟锁井 | 建议：① 报表自动生成率作为验收口径（长庆 99.5% 行业先例）；② 历史回放补"时间轴拖拽"交互描述 |
| **⑦ 拓扑视图** | 电网"一张图"；油田大屏 C 位井位地图/管网图；瀚云设备状态色块（绿/黄/蓝/红/灰） | **建议提升为驾驶舱 C 位组件**（当前在独立界面，业界惯例是 C 位常驻） |
| **⑧ 系统管理** | 角色驱动视图（Azure 四角色/三一三层）；审计日志（ThingsBoard Audit Logs 页签） | 建议：① 加"角色化界面裁剪"描述（厂长/调度/运维千人千面，大屏+PC+移动三端）；② 审计日志对齐"操作全留痕"已有 |

## 5. 三个主要差距与行动项

1. **缺业务结果感**：业界领导驾驶舱强调结果性指标（产量/时率/覆盖率）优先于过程性指标。我们五项全为过程指标 → **行动**：顶部 KPI 区将"链路健康率、采集完整率"包装为结果口径（对标"采油时率 98.9%""数据项在线率"行业语言），而非"设备在线率/采集数据量"过程语言。
2. **缺视觉锚点**：业界 C 位普遍是地图/拓扑/孪生模型 → **行动**：驾驶舱 C 位用"全油田采集链路拓扑图"（作业区-设备-链路，状态着色），等效电网"一张图"惯例。
3. **刷新频率无权威规范**（如实声明未找到）→ **行动**：按业界惯例自定并写入界面说明：KPI/告警秒级（WebSocket）、趋势 5-30 秒、交互响应 ≤1 秒。

## 6. 差异化机会

**断网缓存补传进度界面**：业界公开渠道零命中（映翰通仅把链路事件归入事件告警，无进度可视化）。本项目已具备"断网本地缓存、恢复后按时序补传、去重幂等"功能（报价表板块四-【A】计价项），补传进度可视化（离线台数/补传进度条/时序对齐校验）是**业界都没有的界面亮点**——领导视角："链路断过也能看出数据补回来了"，评审加分项。
